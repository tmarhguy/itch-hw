=== 2026-08-02 — Ethernet cable — lab bring-up

++++
<div class="log-entry">
<p><strong>Date:</strong> 2026-08-02</p>
<h4>Context</h4>
<p>In my understanding of ITCH, market data should flow continuously into the system so the FPGA can act on it. The end-to-end path matters: <strong>data in → decision → data out</strong>, without shortcuts that skip real ingress.</p>
<h4>Update</h4>
<p>Ordered an Ethernet cable for the Nexys A7; it arrived and is ready for testing.</p>
<h4>Goal</h4>
<p>Exercise the full workflow on hardware:</p>
<ol><li><strong>Data in</strong> — live UDP / Mold-wrapped ITCH over the RJ45 link</li><li><strong>Decision</strong> — parse messages, maintain the order book, update BBO</li><li><strong>Data out</strong> — visible feedback on the board (LEDs, 7-segment) as proof the pipeline ran</li></ol>
<p>Next step: build with <code>USE_ETH=1</code>, program the board, and send test traffic with <code>tools/send_itch_udp.py</code> (see <code>docs/board_eth_setup.md</code>).</p>
